# RSAD: Request, Staging, Assignment, and Delivery
A train yard and inter-network train management system

[Overview] overview of train network, basically just like the vanilla UI. Can click on a train to view its current routine and progress. Has buttons to navigate to the next tabs, but really it's just an overview

[Yard Logistics] this is the "R" of RSAD. It'll show a graph-like UI (think blueprints for Unreal Engine? If I can make that work, idk if I can) A "Yard" is a collection of trains and stops that has localized logistics. Trains can only be assigned to one yard, but stops can be assigned to multiple. So you can set up a "global" yard that handles logistics to and from other yards via a dropoff/pickup stop that is shared with that local yard. This tab lets you dictate the conditions that a stop checks before submitting a logistic/dispatch request to the yard. The important difference between this and LTS or CS, is that the conditions for request are freeform. This isn't an "Item Logistics" system, this is a "Train Logistics" system. See next tabs for more details, but essentially you can create check functions and routine functions. check functions can be assigned to stops to check for circuit conditions or local yard values before issuing a dispatch request. Something simple would be like (Here things within {} is a system node, things like inputs into the function or outputs. Things in [](params) are checks or functions.) {On Yard Updated}>[Are Contents Empty](staged)>Yes?>{Request From}(constA, fuzzy, 2_wagons) Here, when the yard is updated (not per tick, it's a roundrobin update), here it checks if the contents of something are empty, here checking if the staged train/wagon is empty (so the one that is currently parked at this stop) then it issues a request to the logistics system for 2 wagons from the constA stop. Each stop has a unique ID name that can be changed (but must be unique) and a shared ID name, both set from the stop GUI. here constA is also set from the stop GUI that is requesting the train, and is being used to determine which stop it requests from (similar in usage to the wildcards that are in vanilla 2.0). fuzzy is a toggle to determine whether the input name is the shared ID or the unique ID, fuzzy being the shared ID. There's a lot more advanced "nodes" that I can imagine being used like having an RSAD interface be able to write signals to a specific yard that can be used in conditions, or having a single longer train have 10 wagons that get sorted into their deposits or having all trains return to a depot when commanded to.routine functions are more advanced and are used in [Routines] in order to chain routines to make complex conditionals.

[Train Routines] this is the "D" of RSAD. Used to plan out routines/schedules for trains to perform. Stops must be assigned a "group". Train routines will get a train from one stop group, to another stop group. So continuing the above example, say the train needs to turn around before arriving at the requester. The routine's source group would be assigned to the group that the fuzzy constA stop is in, and the goal group would be assigned to the group of the requester. The routines can call on procedures from the next tab as well. The routine would look like {Source Arrival}>[Take Wagons](2, Backwards)>{Goto}(constAGroupTurnaround, fuzzy)>{Goto}(goal)>[Decouple All Cargo]>{Finish}(Must Leave). Pretty complicated, but essentially [Take Wagons] is a stop procedure that couples to, then takes some wagons from the stop and moves backwards from the arrival direction to realign the wagons. {Finish} Is a system node that ends the routine, and Must leave states that this train must be given another routine before any other trains in the yard. Reminder that this is a train logistics system, not an item logistics system (I prefer to call Cybersyn and LTS item logistic systems with a focus on trains as the transportation). RSAD moves trains, not items. The above examples are how it may be used to move items but it's an expansive system that should allow for you to dictate when trains move and with what purpose. Trains also are multipurpose, so you can have 1 train that delivers all the items, and 1 train that sorts those delivered wagons to the places they need to go. routine functions can be used to add conditionals and complex behavior tree-like features. Basically they can just return values that the Routine can branch of based on.

[Stop Procedures] step by step procedures that can be assigned to stops. They're used with Routines to expound on the actions performed by the trains. Like the above [Take Wagons](count, direction) procedure would be something like(| | dictates a return or local value) {Start}(count, direction)>{Couple}(Forward)>{Move}(|count| in wagons, |direction|)>{Decouple}(|count| from arrival front carriage)>{End}. Then they're used in the routines. This whole mod is definitely not for beginners and would likely only ever be used by experienced users or programmers.
